# 对话方式与房间

## 选一种对话方式

| 方式 | 你会看到什么 | 智能体怎样分工 |
| --- | --- | --- |
| 单角色与世界演进 | 和一位角色交流，外面的世界也会变化。 | ChatAgent 扮演该角色，EnvAgent 管理已确认的事实和变化。需要查证时，搜索遵循角色能够知道的范围。 |
| 群像与世界演进 | 打开一个房间，选择其中的一条聊天。一位角色可以加入同一房间内的多条聊天。 | 每位角色保留自己的会话、记忆和搜索会话。EnvAgent 管理该房间内的聊天和成员。每条聊天的消息会作为标明来源的系统消息，交给已加入的角色处理。 |
| 桌游主持 | 和主持人交谈。主持人描述场景、解释规则、处理行动后果，你决定怎么行动。 | ChatAgent 做主持人，可用桌游技能掷骰。EnvAgent 管理世界。搜索优先找规则和背景资料，并区分原始规则与变体。 |

群像与普通预设使用不同的对话结构。确定类型后，要用另一种结构就创建一个新预设。单角色和桌游都使用普通对话结构。

## 群像预设的角色与状态设计

群像房间需要至少两个角色和一条 Chat。PresetAgent 为每位人物定义稳定的 `id`、显示名、个人动机和视角，为每条 Chat 指定成员 ID。应用为新 Room 和其中每条 Chat 分配各自的 UUID。默认按场景安排少量共享 Chat，同一人物可以出现在多个场景。例如深夜食堂可以有厨房和大堂，老板加入两处，顾客在大堂交流。

**Room 中每位人物都独占一个 ChatAgent。** 房间并发准备所有人物及其可选的 SearchAgent。用户留在 Room 期间，所有人物持续接收已加入场景的消息，独立决定何时行动、发言或等待。用户切换场景或返回房间概览时，角色继续工作。角色通过 `chat_send` 向已加入的 Chat 发言。EnvAgent 管理世界和成员关系，通过 Chat 或私信告知相应人物。

人物的会话、记忆和技能状态以 **Room 和人物 ID** 定位。重开 Room 时，各人物从自己的持久化会话继续。新 Room 从预设的初始定义开始。聊天消息保留来源及发送者，并送达有权限的人物。某人可以在后续交流中转述自己的所见，预设需要定义这种转述的许可与后果。

新 Room 在所有角色及其场景开场准备完毕后开放。人物在准备阶段用 `room_progress` 报告进度，用 `room_ready` 确认准备完成，并通过 `chat_send` 发布开场发言。用户进入任一场景即可看到已发布的开场并发送消息。有协调开场需求时，请在问候指令中写清每个场景由谁开口，允许其余角色按自身动机保持安静。

PresetAgent 通过 `configure_experience` 的 `ensemble.loading_messages` 写入 3–6 句轮播文案。用用户正在使用的语言，从世界的地名、日常景物、声音或物件里取材，每句只写一个短画面。避开秘密、未发生的剧情以及虚构的加载进度。空间站的例子包括「观景窗外，一排航标灯正掠过。」「货舱门口，昨晚的值班表还夹在板上。」房间的实际准备进度由界面显示。

PresetAgent 设计群像时，应先列清每项状态的归属、修改者、可见者和同步方式。

- **Room 状态**记录可共享的世界事实、任务阶段和公共事件。用预设插件的 `room` 状态作为权威记录，由被授权的角色通过插件业务工具确认并修改。为场景定义新 Room 的初值和推进条件。
- **Chat 状态与消息**用于某个 Chat 内的约定、局部线索和成员之间的沟通。需要结构化读取的数据使用插件的 `chat` 状态。角色通过 `chat_send` 向已加入的 Chat 发送消息，EnvAgent 用 `notify_chat` 定向发布。用稳定的 Chat ID 区分同名频道。
- **人物私有信息**放在人物会话、私信或明确限定角色的插件状态中。单条 Chat 的秘密留在该 Chat 的适用范围内。Preset scope 适合各 Room 共用的规则和起始模板。
- **同步流程**先由插件校验并提交新修订，再向应知角色发布带来源的 Chat 消息。接收方可以通过插件 Skill 读取、订阅结构化状态，并在下一次行动前按当前修订核对关键事实。对会重试的事件定义稳定标识。用修订号检测并发修改，遇到冲突先重新读取再判断。

需要实现共享状态时，向负责该预设的 PluginAgent 提供状态字段、作用域、读写权限、事件与验证情景。用一个 Room 内至少两条 Chat 验证共同成员能衔接状态、非成员拿不到局部信息、同一事件重复送达只提交一次。再核对重新打开 Room 后的恢复和不同 Room 的隔离。实现细节见[插件联动指南](../plugins/automation.md)。
