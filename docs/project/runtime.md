# 运行路径

客户端负责界面、网络和系统 I/O。HarnessCore 维护会话与任务顺序，接收一个命令后会发出流式事件。模型响应分块和平台 I/O 回复可以在长任务中直接送达核心。Android 使用 JNI，桌面使用同一套 C ABI。

普通聊天有一个直接面对用户的 ChatAgent。群像中的每个 Room 包含一条或多条场景 Chat 和一个角色阵容。Room 内共享 EnvAgent 和世界状态。每位人物独占自己的 ChatAgent 和可选的 SearchAgent。打开 Room 时并发准备各角色的会话，由角色调用 `room_ready` 确认会话准备完成。场景开场完成后开放房间，中途退出可以重新打开并继续准备。房间开放期间，角色独立接收已加入场景的新消息，按自身视角决定发言或等待。选中 Chat 或回到房间概览只改变前台视图。离开 Room 时取消角色工作并释放运行资源。

角色的私信使用独立的会话和搜索记忆，打开时按需准备。场景页显示角色的活动状态，详细轨迹通过私信页查询。

## 智能体运行时

- Chat、Env、Preset、Search、Fetch、Plugin、Temporary、Title 和插件短生成统一通过 `AgentSession.Factory` 创建会话。角色声明身份、模型路由、存储范围、业务 Skill 和宿主权限。群像提供参与者作用域。标题与插件短生成使用当轮内存会话和空业务工具目录。
- `AgentSession` 在每次模型请求前刷新 Skill 目录，保留仍获授权的已激活技能，并用 `SessionInstructions` 生成系统提示词、技能和工具定义的变更帧。随后估算模型实际输入，判断并应用压缩，再使用同一循环处理流式响应、工具调用、转向输入、取消和保存。可继续的会话在提交后可以预生成后台检查点。单轮任务也经过请求前的用量和压缩判断。
- 一次任务会持续处理模型回复和工具调用，直到正常完成、收到取消或发生错误。模型和工具没有按次数结束任务的固定上限。模型的上下文窗口和单次回复上限由提供商配置决定。
- 模型发送方法为 `AgentSession` 私有实现。压缩器调用会话提供的分支回调，通过普通会话循环和原来的模型生成检查点。临时分支复用正常分支的数据库快照，追加专用系统消息，只提供会话记忆和历史读取工具。用量估算和发送共用同一个协议请求构建器，宿主负责网络和平台 I/O。业务智能体提交任务定义与业务退出条件，运行时负责处理每个模型轮次。
- 会话创建、分支及插件读取使用 `SessionFiles` 的路径。对话和群像使用同一附件预处理及交互轮收尾。会话消息投影统一剔除内部指令变更帧和隐藏记录，插件按现有授权访问。SQLite 原始历史、模型当前上下文和用户可见记录具有各自的用途。
- 回复选区以 `{id, kind: "quote", text}` 作为消息附件，引用正文随对话、分支和导出保存。模型请求把它标记为引用资料，群像角色在收到的原消息中一并看到引用。
- 本轮模型快照同时约束请求、附件采样、工具结果裁剪和检查点。插件工具的授权同时用于生成工具目录和执行工具。轮次失败时已接收的转向输入仍会保存，群像通过 Room 消息标识避免重复投递给已消费的角色。
- 工具失败回执包含 `diagnostic`，其中 `tool` 是实际工具名，`skill` 是当前可识别的归属，`code` 和 `phase` 表示错误类别与阶段，`next_step` 提供下一步排查建议。参数解析、Skill 未激活、权限、平台超时和插件处理函数失败使用不同诊断。原工具回执的错误和退出状态继续保留，显式取消仍会结束当前任务。

此前各入口自行创建并补配会话，技能刷新依赖调用方是否提供可选回调，单轮生成还通过空任务技能条件跳过了技能装配。当前由工厂一次性绑定能力，每轮无条件运行技能刷新。架构测试检查私有发送入口，角色矩阵测试验证工具变更后下一次请求携带相同格式的 Delta。

插件与智能体的分工由 [清单与 Skill](../plugins/skills-settings.md) 决定。插件可以接收 [Actions 与宿主事件](../plugins/runtime.md)，并通过持久化状态和卡片与智能体、用户交互。状态更新属于插件业务工具，智能体可读取和订阅授权投影。
